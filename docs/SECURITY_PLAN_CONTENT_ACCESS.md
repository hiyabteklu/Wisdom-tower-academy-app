# ACTIVE PLAN: real content security (locks enforced by the server, not just hidden in the app)

> Repo is PUBLIC: no secrets, no student data. Owner rules: `docs/OWNER_RULE_PLAN_FIRST_PUSH_TO_MAIN.md`.
> Owner goal (plain): he controls every material from the admin dashboard (lock / unlock a package, hub, chapter or single material). Locked content must NEVER reach a student who is not allowed. App may be shared as an APK on Telegram before Play Store approval, so it must survive someone taking the APK apart. Honest limit: no app is 100% reverse-engineering-proof; the real protection is that locked content stays on the server.

## S5 DESIGN (revised 2026-10-20: scope is paid PDFs only)
PROBLEM: all PDFs sit in ONE Appwrite bucket readable by role "Any". `appwriteViewUrl(storage_path)` builds `<endpoint>/storage/buckets/<bucket>/files/<fileId>/view?project=<id>`. Anyone who learns one Life Savers file id (the list is public today) downloads it free. A bucket-level "Any" role cannot be removed without also closing the free books.
CHOSEN APPROACH: **a second, PRIVATE Appwrite bucket for paid PDFs** (no "Any" role, file security on) plus **Appwrite file tokens** (documented: server call `POST /tokens/buckets/{bucketId}/files/{fileId}` with an API key and optional expiry; a token works in the view/download address and needs no bucket or file permission). The student never gets the API key. Flow: student taps a paid PDF -> app asks a Supabase Edge Function with the student's login -> the function asks the database "may this student open this PDF?" (same lock + Paid mode + purchase rules as `open_resource`, through `content_guard.resource_visible`) -> only if yes it creates a short-lived token (about 10 minutes) and returns the file address -> app downloads and keeps the file as it does today.
KEEPING OLD APPS AND BOOKS WORKING: `storage_path` of free books stays `appwrite:<fileId>` (public bucket, unchanged). Paid PDFs use a NEW prefix `appwrite-paid:<fileId>` (private bucket), which old apps do not understand (they simply cannot open them, which is the point). The app treats `appwrite:` as today and `appwrite-paid:` through the Edge Function.
WHY NOT the alternatives: Supabase Storage signed URLs need every PDF moved off Appwrite and the free plan storage is small; streaming every PDF through an Edge Function burns the free bandwidth quota.

- **S5a (SUPABASE, additive, breaks nothing):** (1) RPC `open_book(p_id uuid)`: signed-in only, same checks as `open_resource`, returns only `{status, storage_path}`; admins allowed as in `open_resource`. (2) generated column `learning_resources.has_file boolean` (storage_path not null) so a list can say "has a file" without exposing the id. (3) Edge Function `book-url` (JWT required): calls `open_book` with the caller's token, then Appwrite create-token with `APPWRITE_API_KEY`, returns `{url, expires_at}`. Record migration and function names in the change log. The website proxy `/api/content/pdf` never serves the private bucket (it has no key), so Life Savers on the website stay unavailable until the website is changed (not a priority).
HONEST LIMITS: a student who legitimately downloaded a PDF keeps the file on the phone even if the owner locks it later; a token is a secret for its few minutes, so a student could pass a link to a friend for that short time, but the friend cannot get a new one.

- **Migration must be staged:** build and verify a higher-version, same-package, same-signing-identity replacement; publish its direct APK and exact Telegram post; warn students through social media and Telegram; allow the owner-approved grace period; then enforce the new minimum and server-side denial for unsupported app versions.

- This 2026-11-05 owner clarification supersedes the old “leave FLAG_SECURE off until the app is finished” direction for the next production release. The new build should protect student screens while keeping only the narrowly scoped, fresh-server-verified admin export exception described in the release hardening roadmap. Do not turn protection off globally for admins.
