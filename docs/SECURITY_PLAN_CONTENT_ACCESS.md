## S5 DESIGN (written 2026-10-20 before any code; owner rule: plan first)
PROBLEM (verified in code): book PDFs sit in ONE Appwrite bucket that anyone can read (role "Any", see `BookFileStore.kt`). The app builds the direct address `<endpoint>/storage/buckets/<bucket>/files/<fileId>/view?project=<id>` from the public `storage_path` (`LearningContentRepository.appwriteViewUrl`, used by `HubItemListScreen`, `StudyWorkspaceScreen`, `BookFileStore`). Anyone who learns one file id (the list is public today) downloads the book with no check. The website proxy `/api/content/pdf` also reads the same public address with no lock check.
CHOSEN APPROACH (keeps the books in Appwrite, no migration, no new storage cost): **Appwrite file tokens** (documented: server call `POST /tokens/buckets/{bucketId}/files/{fileId}` with an API key and an optional expiry; a token works in the view/preview/download address and needs no bucket or file permission; anyone holding it can open that one file until it expires). The student never gets the API key. Flow: student taps a book -> app asks a Supabase Edge Function with the student's login -> the function asks the database "may this student open this book?" (the same lock + Paid mode + purchase rules as `open_resource`) -> only if yes, the function makes a short-lived token (about 10 minutes) and returns the file address with that token -> app downloads and keeps the file as it does today.
WHY NOT the alternatives: Supabase Storage signed URLs need every PDF moved off Appwrite and the free plan storage is small; streaming every PDF through an Edge Function burns the free bandwidth quota.
SLICES:
- **S5a (SUPABASE, additive, breaks nothing):** (1) RPC `open_book(p_id uuid)`: signed-in only, same checks as `open_resource` through `content_guard.resource_visible`, returns only `{status, storage_path}` (no `body_md`, no `meta`); admins allowed as in `open_resource`. (2) generated column `learning_resources.has_file boolean` (= storage_path is not null and starts with `appwrite:`) so the list can say "has a file" without exposing the id. (3) Edge Function `book-url` (JWT required): calls `open_book` with the caller's token, then Appwrite create-token with the secret `APPWRITE_API_KEY`, returns `{url, expires_at}`. OWNER ACTION (plain steps to give him then): in Appwrite console create an API key for this project with the permissions it asks for to read files and create file tokens (we verify the exact names with one test file first), and paste it into the Supabase dashboard as a function secret named `APPWRITE_API_KEY`. NEVER put the key in git or in chat. Record the migration and function names in the change log.
- **S5b (APP, additive):** new `LearningContentRepository.bookUrl(item)` asks `book-url` with the student token; on success downloads with the token address; while `LEGACY_BOOK_PUBLIC_URL = true` (new constant, same idea as `LEGACY_DIRECT_READ`) any failure falls back to today's public address. `BookFileStore` and the size probe use `bookUrl`. The list shows the book as available from `has_file`.
- **S5c (BREAKING, only after the owner tested S5a+S5b on a phone; do together with S4):** (1) owner removes role "Any" read from the Appwrite bucket (and keeps file security as the console suggests) -> old app versions and the website proxy can no longer read books; (2) set `LEGACY_BOOK_PUBLIC_URL = false`; (3) remove `storage_path` from `LIGHT_COLUMNS` and revoke the `storage_path` column for `anon` and `authenticated` (`open_book` is a definer function, it still reads it); (4) the website proxy `/api/content/pdf` must be given the API key header and a lock check, or accepted as broken (website is not a priority: TELL THE OWNER before step 1, because the in-app web pages that still go through `/api/content/pdf`, see `MainActivity.kt` around lines 2886 and 3000, stop showing books).
HONEST LIMITS: a student who legitimately downloaded a book keeps the file on the phone even if the owner locks it later (same as any downloaded file); a token is a secret for its few minutes, so a student could pass a link to a friend for that short time, but the friend cannot get a new one.
