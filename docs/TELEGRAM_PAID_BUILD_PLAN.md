## 3. Design
1. ONE code base. A build switch `BuildConfig.PAID_UI` (false by default, true only when Gradle runs with `-PpaidUi=true`). Every paid screen checks it, so the Play build keeps today's behaviour.
2. CI makes two APKs per run: `Wisdom-tower-academy-APK` (Play, as now) and `Wisdom-tower-academy-TELEGRAM-APK` (paid UI on). The AAB stays Play-only. The Telegram step is `continue-on-error` so it can never break the Play build.
3. PRICE SOURCE (owner order): the admin dashboard catalog (`catalog_items.price_etb`) ONLY, no built-in fallback; the last good copy is saved on the phone for offline use (`data/content/PackagePrices.kt`). No dashboard price = nothing shown for that package.
4. Paid build only: package cards show the price; the "Package required" card shows package name, price and a Buy button that opens the website checkout inside the app (signed in) and an Orders link; after the student comes back the app re-reads ownership.
5. Website (owner approval needed, separate repo): `IS_FREE_MODE` reads a Vercel env var instead of being fixed, so the owner switches paid mode with no code push; also decide about `FREE_FOR_REGISTERED_PACKAGE_IDS`.
6. Database (owner, no code): finished courses locked as `require_purchase`, unfinished ones left `open` as the promotion; `system:enforce` set to `locked`.
