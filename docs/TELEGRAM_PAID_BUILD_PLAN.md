## 3. Design
1. ONE code base. A build switch `BuildConfig.PAID_UI` (false by default, true only when Gradle runs with `-PpaidUi=true`). Every paid screen checks it, so the Play build keeps today's behaviour.
2. CI makes two APKs per run: `Wisdom-tower-academy-APK` (Play, as now) and `Wisdom-tower-academy-TELEGRAM-APK` (paid UI on). The AAB stays Play-only.
3. PRICE SOURCE (owner order): the admin dashboard catalog (`catalog_items.price_etb`) ONLY in the app, no built-in fallback; the last good copy is saved on the phone for offline use (`data/content/PackagePrices.kt`). No dashboard price = nothing shown for that package.
4. Paid build only: package cards show the price; the "Package required" card shows package name, price and a Buy button that opens the website checkout inside the app (signed in) and an Orders link; after the student comes back the app re-reads ownership.
5. PAYMENT APPROVAL (owner order): ADMINS ONLY, no automatic approval. The student enters the TX ID or uploads a receipt; the order is always saved `pending_verification`; the admin approves it in the dashboard.
6. Website payment screens are for the Telegram app; the public website access is the owner's own decision (owner will handle it).
7. Database (owner, no code): finished courses locked as `require_purchase`, unfinished ones left `open` as the promotion; `system:enforce` set to `locked`.
